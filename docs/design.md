# 设计决策

README 讲 posts 做什么、怎么部署；这里记录业务规则和背后的理由，供修改行为前参考。

## 转换原则

- **只转格式，不改内容。** 正文文字一字不增删改，不翻译、不纠错、不总结。存档的价值在于忠实于原文。
- **只保留正文。** 导航、侧栏、评论区、推荐阅读等正文之外的内容一律舍弃。
- **正文范围由模型判断，不为具体站点写规则。** 网站千差万别，逐站维护规则不可持续；prompt 只讲通用原则，模型依据页面结构、class 名称和内容自行判断。
- **发布日期**优先取页面上的日期（正文、署名、meta、JSON-LD）；判断不出时用转换当天。页面给出精确时间时保存为带时区偏移的 RFC 3339 时间，否则只存 `YYYY-MM-DD`。文章按发布日期的年/月归档。
- **作者**取页面署名，原样保存；判断不出时为空。
- **slug** 是概括标题的英文短语，非英文标题意译成英文，用作文件名。
- 长文章第一版不分段，整篇交给模型；超出能力就按失败处理。

## 上传与预览

- 上传完成后进入 `ready`（待转换），只读取标题、来源和保存时间，原始 HTML 按上传字节保存为 `.work/<id>/original.html`；此时不清洗、不提取资源、不调用模型。
- 上传后打开第一篇成功上传的网页，批量上传的其他网页留在列表中待转换。待转换文章可从列表再次打开。
- 原始 HTML 在覆盖整个视口的 iframe 中展示，悬浮按钮可用鼠标或触屏拖动，菜单提供“开始转换”和“返回列表”。返回列表保留待转换状态；开始转换成功入队后返回列表。
- 转换完成默认展示 Markdown 页面；可拖动按钮在原文和转换结果两种视图中始终保留，通过菜单的“查看原文 / 查看转换结果”来回切换，切换保留按钮位置。排队、转换中或失败时也可查看原文和处理状态。历史文章缺少原始 HTML 时禁用查看原文。
- 原始 HTML 接口鉴权并按用户隔离；响应 CSP 与 iframe sandbox 禁止脚本、同源权限、表单和跳出预览。保留内联样式及 data/blob 图片、字体和媒体，不加载外部资源。
- 列表按发布日期降序，只比较日期部分，列表也只显示日期；尚无发布日期时使用上传日期（UTC），同一天按文章 id 降序。转换完成后按实际发布日期重新排序。

## 清洗：送进模型之前

清洗后的 html 会原样放进 prompt，所以清洗的目标有两个：去掉对判断正文没有帮助的内容以节省 token，同时保留模型判断正文所需的线索。

删除的内容：

- **Automa 插件面板**：精确匹配 `div#automa-palette`，整棵子树删除（包括声明式 shadow DOM 和内嵌资源），在展开 shadow DOM、提取资源之前执行。不依赖它位于最后一行或文档末尾；原始 HTML 不受影响。这是对已知浏览器插件注入内容的清除，不是按站点裁剪正文。
- **样式和脚本**：css、js、内联 svg、事件属性。只被样式引用的资源（如字体）随样式一起丢弃。
- **SingleFile 标记为隐藏的元素**：保存时页面上看不到，去掉 css 后反而会显现出来。
- **`data-*` 属性**：对判断结构帮助不大；页面资源都在 `src`、`poster` 等标准属性里。
- **utility class**（Tailwind 一类的 `px-3`、`text-sm`、`lg:flex`）：只表达样式，不表达结构，在现代前端站点上能占清洗后 html 的一半。
- **页面框架**：不在文章（`article`/`main`）里的 header、nav、footer、aside。它们是站点框架，不会是正文。
  - 但包含一级标题的保留：有些主题把文章标题放在文章外面的 header 里。
  - 文章里面的目录、上下篇导航、侧注保留，交给模型判断。

保留的内容：

- **有语义的 class**（如 `topic_content`、`reply_content`）：全 div 或表格布局的页面只能靠它们区分正文和回复、导航。实测 v2ex 帖子里，模型正是靠它们正确保留了楼主的附言、舍弃了回复。
- **具名 meta 和 JSON-LD**：它们是元数据，帮助模型判断标题和发布日期。
- **声明式 shadow DOM** 的内容展开为普通节点，因为那是页面实际显示的内容。

评论区这类无法按标签识别的噪音不在清洗阶段处理，仍由模型判断。不用 Readability 一类的正文抽取预先裁剪：一旦切错，正文就丢了，这和"由模型判断正文范围"冲突。

参考数据：OpenAI 文档页清洗后从 54 KB 降到 20 KB；v2ex 帖子（表格布局、语义 class）不受影响，约 32 KB，大头是回复区。几十 KB 的输入约一两万 token，远小于模型上下文；转换耗时主要花在逐字输出正文上。

## 内容校验

模型可能改写、翻译或编造文字。转换后检查 Markdown 的每一段文字都能在清洗后的页面里找到（只比较字母和数字，忽略格式、空白和标点）。

- 页面文字远多于 Markdown 是正常的（舍弃了导航等），只检查反方向。
- 数学公式只比较 TeX 源码。KaTeX 的公式在页面里有渲染结果和 MathML 两份文字，Markdown 里只有一份 TeX（如 `$x^2$`），整页文字照搬会对不上。带 TeX 源码（`annotation encoding="application/x-tex"`）的公式只取源码，不在 prompt 里另外规定公式写法。
- 不通过不算失败：文章照常保存，在文章页显示警告和找不到的段落，由人判断。
- 警告列出全部找不到的段落，且不截断：只看到一部分或半段文字，没法判断问题出在哪里。

## 存储

- **Markdown 只存磁盘，不进数据库。** 数据库只存元数据（标题、发布日期、作者、slug、来源、状态、警告等），文章目录本身就是一份可直接浏览、备份的存档。
- 文章目录为 `<年>/<月>/<id>/<slug>.md`，资源放在同级 `assets/`。年月取发布日期；id 保证同名文章不冲突。
- **只保留 Markdown 实际引用到的资源**：站点 logo、导航图标等随正文之外的内容一起舍弃。
- 资源按内容哈希命名，同一页面里的相同资源只存一份。
- 原始 HTML 和转换前的清洗结果保留在工作目录（分别为 `original.html`、`index.html`），失败后可以重试；成功前将原始上传字节保存为文章目录中的 `original.html`，将本次实际传给转换器的 HTML 字节保存为同级 `cleaned.html`，再删除工作目录。`cleaned.html` 用于检查模型输入，不重新清洗或美化；原始 HTML、清洗结果与本地文章一起删除，zip 仍只包含 Markdown 和资源。旧版本遗留的待转换/失败文章没有原始 HTML 时继续使用已有清洗结果；已丢弃的历史原文无法恢复。

## Markdown 手动编辑

- 转换完成、尚未导入 Palace 时，文章页提供“编辑 Markdown”，使用按需加载的 CodeMirror 6 纯文本编辑器，显示行号并开启自动换行，支持撤销与重做。
- 点击“保存”通过按用户隔离的 `PUT /api/posts/<id>/md` 将 UTF-8 正文原样写回原 Markdown 文件（上限 16 MB）；使用同目录临时文件替换，保存后更新阅读预览和后续下载、导入使用的内容。空文件也允许保存。
- 编辑只改 Markdown，不修改本地元数据、归档路径、原始/清洗 HTML 或资源，不重新调用模型或清理资源。内容校验警告保留为转换时的报告，不随手动编辑重新校验。
- 未保存时关闭编辑弹窗需点击“放弃修改”，刷新或关闭页面会触发浏览器的未保存提示；保存失败保留草稿并显示错误。
- Palace 导入排队、进行中或成功后禁止保存；导入失败时允许修改后重试。保存、请求导入与删除在服务内互斥，确保入队前保存完成。

## Palace 手动导入

- 转换完成只保存本地文章，**不会自动导入**。列表与文章页提供“导入 Palace”，点击先打开可编辑对话框，展示 `article.json` 对应的标题、原文网址、发布日期和可选作者。首次从本地文章元数据预填；已提交过的导入回填上次确认的值。缺失项由用户补齐，取消不保存、不入队；只有点击“确认导入”才通过 `POST /api/posts/<id>/import` 提交 JSON 并入队，历史已转换文章也适用。
- 服务端在入队前校验必填项、http/https 原文网址、日期（`YYYY-MM-DD` 或带时区的 RFC 3339）及 CLI 字段长度约束。不完整或非法的信息立即返回错误，对话框保留用户输入供修改。
- 发布日期输入框右侧提供日期 / RFC 3339 切换，只修改当前输入值；每次日期转 RFC 都以当前日期生成浏览器本地零点，使用该日期的本地时区偏移。RFC 转日期保留原值的日期部分、舍弃时间和时区，不换算日期、不缓存旧时间；空值或非法日期禁用切换。
- 用户确认的导入元数据与入队状态在同一数据库事务中保存，独立于转换元数据；修改导入信息不改变原始 HTML、Markdown、本地来源记录、归档路径或排序。刷新、失败重试、服务重启均保留已确认的信息。
- 上传前按已确认的元数据在文章目录生成 `article.json`，调用 `pal article upload <文章目录>`；Markdown 和资源保持原样，由 CLI 按其规则收集媒体。旧版本已入队但尚无确认信息的任务沿用原有文章元数据。
- 导入与转换独立：数据库记录 `palaceStatus`（未请求时为空，之后为 `queued → importing → done/failed`）、远端文章 ID 和错误。转换完成状态及本地阅读、下载不受导入失败影响；失败后手动重试仅再次上传，不调用转换器。
- 导入任务与转换共用串行 worker，导入排队时可能等待当前转换完成；刷新页面不取消任务。启动时只恢复已请求且中断的导入，不为未请求或失败的文章自动入队。CLI 运行上限为 5 分钟。
- CLI 从进程环境继承 `PAL_URL` 和 `PAL_TOKEN`，token 不进入参数或数据库。所有导入归属该 token 的 Palace Owner；posts 的导入接口仍按登录用户隔离文章。部署实例使用固定的 Palace 目标及 Owner，已有导入记录不随环境配置变更自动重置。
- 同一 Owner 下相同原文 URL 按 Palace 规则幂等，返回已有文章且不更新其内容；响应不确定时可安全重试。已成功导入的本地记录拒绝重复入队。删除本地文章不删除 Palace 副本；正在上传的文章禁止删除。

## 用户与隔离

- 通过 OIDC（Authelia）登录，文章按用户隔离，每个用户只能看到和操作自己的文章，与 homepage 一致。
- 本地开发可以用固定的开发用户跳过 OIDC。

## 转换队列

- 状态流转为 `uploading → ready → queued → converting → done/failed`；只有点击“开始转换”才从 `ready` 入队，失败后可重试入队。清洗和资源提取也在后台 worker 中执行。
- 排队、转换中等状态保存在数据库，前端从接口读取并轮询，等待动画由服务端状态决定；刷新、关闭标签页不会取消后台任务，重新打开后继续显示实际状态。
- posts 持有队列，已入队的文章按上传顺序逐篇串行转换；workflow 服务同一时间也只执行一个工作流，排队时间计入超时。
- 服务重启时，中断的转换重新排队；待转换文章保持 `ready`，不会自动入队。
- 失败（包括模型不可用、超时、输出不合法）标记为失败并显示原因，可在页面手动重试。

## 部署拓扑

- posts 跑在 homelab 的 Docker 里；转换服务 workflow 跑在宿主机上（以当前用户运行，依赖本机的 Codex 登录和 node 环境）。
- 容器里的 `127.0.0.1` 不是宿主机，所以 workflow 监听 Docker 网络 `my-network` 在宿主机上的网关地址。这个地址只有宿主机和该网络里的容器能访问，不对局域网和外网暴露，因此不做鉴权。
- 模型和推理强度在 workflow 的 converter profile 里配置，posts 不关心。
- 镜像只在 CI 构建。
- 最终镜像内置 `/usr/local/bin/pal`，以 musl 静态二进制适配 `distroless/static-debian12:nonroot`。
  CI 先解析 Palace 最新正式 Release 的 `latest.json`，把同一个固定 `PAL_VERSION` 传给 amd64、arm64 构建；
  下载固定版本附件，校验 SHA-256、ELF 架构、无动态加载器和共享库依赖，再复制二进制进最终镜像。
  Node 与解包工具不进入运行镜像。CLI 只在镜像重建时更新；运行时由用户手动触发文章导入。

## 暂不做

- 长文章分段转换后拼接。
- 同一 URL 重复上传时提示或覆盖。
- 查看清洗后的 html。
- 全文搜索。
